# 调研范围与参考项目清单

调研日期：2026-09-14。

## 用户目标

在一个新项目中，浏览并编辑 **Codex 与 Claude Code** 已有 Session 的历史消息，至少覆盖：

- 人类用户发出的消息正文；
- Agent / Assistant 回复的消息正文；
- 定位到具体会话、消息和内容块；
- 修改能写回实际会话存储，并分析恢复原会话后是否会使用修改后的内容。

沿用此前对历史编辑器的目标，把“原地修改且保留后续消息”作为主要评价场景。同时单独研究删除、截断、fork、repair、compact 等操作，不能将这些不同语义都归为“编辑历史”。

本阶段只进行仓库拉取、源码调研、横向比较和融合方案分析，不实现正式应用，也不修改真实 Codex / Claude Code 会话。

## 统一评价标准

1. **机制与作用**：技术栈、入口、数据流、读哪些文件、写哪些文件。
2. **编辑粒度**：用户正文、助手正文、多内容块、reasoning、工具调用及原始记录。
3. **后续历史**：原地编辑是否保留后续记录；删除、回滚、fork 是否改变会话身份或截断历史。
4. **恢复效果**：界面修改、存储写回、恢复成功和模型实际使用新内容，需要分别举证。
5. **一致性**：UUID / parent 链、工具配对、Codex 重复消息表示、压缩快照、索引与 SQLite。
6. **写入可靠性**：备份、原子替换、版本 / hash 检查、并发保护、活动会话检测和异常恢复。
7. **复用成本**：许可证、依赖、维护活跃度、可提取模块、改造范围及是否适合统一双引擎产品。

## 证据等级

- **源码已确认**：提供固定 commit 的文件路径、函数及行号。
- **隔离测试已确认**：说明实际运行的测试、输入与结果，不能把单元测试等同于真实 resume。
- **文档声称**：README 或公开文档中提到，但尚未由实现或运行验证。
- **待验证 / 未知**：无法从当前证据得出结论，尤其是不同 CLI 版本的恢复行为。

Claude Code 的第三方源码分析不等于官方完整源码，也不自动代表当前安装版本；相关推断需要明确标注这一边界。
