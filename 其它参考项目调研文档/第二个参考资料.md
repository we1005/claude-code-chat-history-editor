## Claude Code：我现在最推荐 `es6kr/claude-code-sessions`

仓库：

```
es6kr/claude-code-sessions
```

它的 README 目前主要宣传 browse、search、rename、split、delete message 等，所以一开始很容易把它当作普通 Session Manager。它本身是一个完整 monorepo：

- TypeScript Core
- SvelteKit Web UI
- VS Code Extension
- MCP Server
- MIT License

而且项目仍然相当活跃。([GitHub](https://github.com/es6kr/claude-code-sessions))

但是我直接翻了它 **main 分支的源码**，发现了 README 没有明显宣传的关键功能：

```ts
updateMessageContent(
    projectName,
    sessionId,
    messageUuid,
    newText
)
```

这不是 Revert，也不是 Fork。

它会直接找到 Claude Code JSONL 里面 UUID 对应的那条消息，然后**只修改那条消息的 content**。

也就是说：

```text
U1
A1
U2
A2
U3
A3
```

修改 `A2`：

```text
U1
A1
U2
A2'   ← 真正修改
U3     ← 保留
A3     ← 保留
```

这正是你最开始要求的行为。

而且它不是简单粗暴地：

```js
message.content = "新内容"
```

源码专门考虑了 Claude Code 现代 JSONL 的复杂结构。对于：

```text
user
human
assistant
```

都允许编辑。

如果 `message.content` 是 block array，它按照类型处理：

```text
text
    → 修改 text

tool_result
    → 修改 content
      保留 tool_use_id / is_error

thinking
    → 修改 thinking
      保留 signature 等其他字段

tool_use only
    → 拒绝修改
```

所以不会随便破坏 tool use / tool result 配对关系。

更重要的是，它现在已经不仅仅有 Core API。

Web Server 已经存在更新 message 的 endpoint，最后调用的就是：

```text
session.updateMessageContent(...)
```

Web UI 的 `SessionViewer.svelte` 里面也已经存在 message editing state，并且编辑器会按照上述 type-aware 规则读取对应字段。

还有针对 `updateMessageContent` 的测试。

所以这一点我要修正我前面搜索时的判断：

> **对于 Claude Code，你甚至未必需要自己开发 Editor。`es6kr/claude-code-sessions` 的 main 分支已经很接近成品。**

我会建议你**第一优先先安装它的 Web UI/main branch 实际试一次**。

# 但是 Codex 有一个 Claude Code 没那么严重的问题

这是这次深挖之后我觉得**最重要的一点**。

现在 2026 年 9 月新版 Codex 的 session 已经不应该简单理解为：

```text
rollout JSONL
=
UI history
```

而更接近：

```text
                 canonical source
                       │
                       ▼
              rollout-xxxx.jsonl
                       │
             history projection
                       │
                       ▼
          thread_history_1.sqlite
                       │
        ┌──────────────┼───────────────┐
        ▼              ▼               ▼
 thread_items    thread_turns    thread_history_
                                projection_state
                       │
                       ▼
                 Codex Desktop
```

OpenAI Codex 最近几个 issue 已经把这套机制暴露得非常清楚。

Codex Desktop 的 paginated history 是从 rollout 建立 SQLite projection；`thread_items`、`thread_turns` 和 `thread_history_projection_state` 都是派生数据。官方仓库源码也能看到这些表。([GitHub](https://github.com/openai/codex/issues/38792?utm_source=chatgpt.com))

近期甚至出现不少这种 bug：

```text
rollout JSONL：

U1
A1
U2
A2
U3
A3
U4
A4       ← 全都存在

SQLite projection：

U1
A1
U2
A2       ← 卡住

Codex Desktop：
只显示到 A2
```

模型甚至还能拥有后面的 context，但 Desktop UI 看不到，因为 projection 卡住了。([GitHub](https://github.com/openai/codex/issues/43451?utm_source=chatgpt.com))

所以如果你只是：

```text
coldxx
    ↓
修改 rollout JSONL
```

有可能出现：

```text
rollout：
A2'

SQLite：
A2

Desktop：
A2
```

至少从我搜索当前 `coldxx` 源码的结果看，**我没有发现它针对新版 `thread_items / thread_turns / thread_history_projection_state` 做同步/失效处理。**

因此：

> **coldxx 的 JSONL 编辑核心不错，但如果你准备长期使用，我建议 Fork 后补上新版 Codex projection handling。**

这个反而是我本轮搜索最大的发现。

仓库：

> 编辑用户或助手消息

> 删除单个轮次

([GitHub](https://github.com/XiaoZhi0079/codex-claude-session-manager?utm_source=chatgpt.com))

我进一步查 API，确实不是宣传词。

Claude 有：

```text
/edit-preview
/edit-apply

```

Codex 也有：

```text
/api/edit-preview
/api/edit-apply
/api/edit-restore
```

([GitHub](https://github.com/XiaoZhi0079/codex-claude-session-manager/blob/main/docs/API.md?utm_source=chatgpt.com))

### 它的 Claude 编辑实现非常好

我直接检查了：

```text
src/claude-message-edit.mjs
```

它不是按“整条 message”修改，而是先把一条 message 解析成多个 **editable parts**：

```text
targetId
role
label
locator
text
```

支持：

```text
message_string
block_text
block_value
block_json
attachment
record_field
```

然后只改 locator 指向的那个字段。

因此它甚至比：

```text
es6kr/claude-code-sessions
```

目前的：

```text
一个 message → 一个主要编辑字段
```

更加细粒度。

例如：

```text
Assistant Message
│
├── thinking
├── text block 1
├── text block 2
├── tool_use
└── tool_result
```

理论上它可以让 UI 精确指向其中一个 editable field。

并且有：

```text
expectedText
sourceHash
preview
atomic write
backup
restore
```

防止你打开编辑器以后，Claude Code 又把 session 修改了，然后 Editor 用旧数据把新内容覆盖掉。

### 它对 Codex 的处理更值得借鉴

它没有简单：

```text
rewrite rollout.jsonl
```

而是：

```text
锁定目标 thread
        ↓
检查 rollout SHA-256
        ↓
备份 rollout
        ↓
备份 paginated history DB
        ↓
修改 rollout
        ↓
重新 parse 验证
        ↓
只 invalidate 当前 thread：
    thread_items
    thread_turns
    thread_history_projection_state
        ↓
下次 Codex 打开
        ↓
从新的 rollout 重建 projection
```

它的 DATA-SAFETY 文档明确描述了这一流程。([GitHub](https://github.com/XiaoZhi0079/codex-claude-session-manager/blob/main/docs/DATA-SAFETY.md?utm_source=chatgpt.com))

这个设计非常合理，因为 Codex 官方/社区最近验证过：

删除这三类当前 thread 的 projection 数据后，下一次 `codex resume` 可以根据 canonical rollout 完整重建历史。([GitHub](https://github.com/openai/codex/issues/38792?utm_source=chatgpt.com))

**所以从纯技术完整度来说，这个项目目前甚至是我最喜欢的。**

但它有一个致命问题：

> **没有 License。**

作者自己 README 明确声明：

> 公开可见不等于允许复制、修改、再分发或商业使用。

([GitHub](https://github.com/XiaoZhi0079/codex-claude-session-manager?utm_source=chatgpt.com))

因此：

**可以研究设计、可以运行测试，但我不建议直接 Fork 它然后在它上面长期开发。**

interface AgentAdapter {

```text

system injected context
file history snapshots
...
```

([GitHub](https://github.com/liwala/session-porter?utm_source=chatgpt.com))

> **Patch in place，而不是 Parse → Normalize → Rebuild。**

也就是：

```text
读取原始 JSON
      ↓
定位某个 field
      ↓
只修改该 field
      ↓
其他未知字段 byte/semantic 尽可能不动
```

这对于 Coding Agent session 特别重要。

# 还有一个很重要的区别：修改“历史记录” ≠ 修改“当前模型上下文”

这点如果你以后真做这个项目，一定要在 UI 里标出来。

例如：

```text
U1
A1
U2
A2
...
U50
A50

      ↓
发生了 Context Compaction

Summary / Replacement History
      ↓

U51
A51
```

如果你现在编辑：

```text
U5
```

为：

```text
U5'
```

文件中的**历史记录**确实会变。

但是模型下一轮继续 session 时用的可能已经不是：

```text
U1...U50
```

而是：

```text
Compaction Summary
+
U51
A51
```

尤其 Codex 最近正在大量调整 context compaction / persisted rollout 机制；甚至几天前还有 compaction 改写 rollout 与 projection migration 相互作用的问题报告。([GitHub](https://github.com/openai/codex/issues/44363?utm_source=chatgpt.com))

因此编辑器最好给消息标记：

```text
Historical only

或者

Currently model-visible
```

甚至提供：

```text
Edit transcript only

Edit active context / summary too
```

这会让这个工具从“JSONL 编辑器”升级成真正的：

> **Coding Agent Session Surgery / Session Editor**
